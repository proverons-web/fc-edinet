FC Edinet v2.28.23 — deploy environment recovery (Windows)

Why: a freshly extracted FULL package deliberately has no .env.local,
so npm run deploy:check previously failed on missing Supabase variables.

Fix:
1. Run DEPLOY_FC_EDINET.bat normally.
2. Step [0/8] checks local settings before npm install.
3. If .env.local is missing, it automatically copies the file from the
   newest older sibling folder named fc-edinet-vX.Y.Z, if valid.
4. If no valid previous file exists, deployment stops with clear instructions.
   Copy .env.local from the last working version manually and retry.
5. Existing .env.local files are NEVER overwritten. Values are NEVER printed.
6. Git ignore protection for .env.local is verified before staging files.

Required locally:
NEXT_PUBLIC_SUPABASE_URL=https://<project>.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_<value>

Do not commit or share .env.local. Production server-side secrets belong in
Vercel environment variables, not in the release archive.

The seven mobile layout corrections from v2.28.22 are preserved unchanged.
