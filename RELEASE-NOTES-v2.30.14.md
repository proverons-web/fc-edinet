# FC Edineț v2.30.14 — Real User Performance & Error Monitoring

Основа: v2.30.13 FULL. Публичный дизайн и матч-центр не менялись.

## Реализовано

- `app/components/RealUserMetrics.tsx`: отдельный маленький клиентский компонент с официальным `useReportWebVitals` от Next.js. Собирает LCP, INP, CLS, FCP, TTFB и только число событий `error` / `unhandledrejection`.
- `app/api/rum/route.ts`: тихая запись метрик после валидации формы/источника запроса; при недоступности базы никак не мешает посетителю.
- `database/078_real_user_monitoring.sql`: две защищённые таблицы и серверная атомарная RPC-функция. RLS включён, доступ ограничен `service_role`, лимит 90 событий на IP-HMAC за час, данные хранятся до 35 дней с вероятностной очисткой.
- `lib/rum-report.ts`: p75, разбивка по устройствам, группировка по маршрутам, количество JS-событий без сообщения/стека.
- `/admin/diagnostics/performance`: закрытая администратору панель с периодами 24 ч / 7 д / 30 д, явными ограничениями выборки. В `/admin/diagnostics` добавлен переход и обновлён номер ожидаемой SQL-миграции.
- QA v2.30.14: тест реальной функции процентиля, регистрации метрик, ограничения приватных путей, серверной валидации, безопасности SQL, постраничной загрузки и обновления CI.

## Приватность

В таблице `rum_samples` нет IP, user-agent, куки, идентификаторов пользователя, URL-параметров, текста ошибки или stack traces. Для ограничителя частоты только на сервере рассчитывается HMAC IP с почасовым разделением; временный хэш записывается в `rum_ingest_rate`, хранение до двух суток. Приватные пути `/admin`, `/account`, `/login`, `/register`, `/api` не собираются. Текст и стек ошибок не отправляются. В браузере ничего не записывается в cookie/localStorage.

## Важно

Эта версия не измеряет скорость задним числом и не заменяет Lighthouse или runtime-логи Vercel. Низкая посещаемость может давать недостаточную выборку. Полноценный Next.js production build не был выполнен в среде подготовки: npm Registry недоступен по DNS. До отправки на GitHub установщик выполняет локальные QA, TypeScript и `next build`.

## Миграция

Необходимо вручную выполнить `database/078_real_user_monitoring.sql` в Supabase SQL Editor **до** публикации. На действующей базе изменения автоматически не производились.
