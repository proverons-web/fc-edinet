FC EDINEȚ v2.30.27 — USERS, ROLES & ON-SITE EDITING
=================================================

ЭТО ПАКЕТ ОБНОВЛЕНИЯ ДЛЯ ЛОКАЛЬНОЙ v2.30.26, НЕ ПОЛНЫЙ ПРОЕКТ!

УСТАНОВКА КОДА
1. Сделай резервную копию работающего каталога fc-edinet-v2.30.26 и Supabase.
2. Распакуй папку UPDATE_FC_EDINET_v2.30.27 ВНУТРЬ каталога с package.json v2.30.26.
   Итог: <fc-edinet-v2.30.26>\UPDATE_FC_EDINET_v2.30.27\APPLY_FC_EDINET_2.30.27.bat
3. Запусти APPLY_FC_EDINET_2.30.27.bat.
   ЛИБО, если нужна новая ПОЛНАЯ папка из GitHub, запусти
   BUILD_FULL_FROM_GITHUB.bat: скачает проверенный коммит v2.30.26 и применит патч.
   При несовпадении файлов или версии обновление блокируется ДО записи.
   Оригиналы сохраняются РЯДОМ с проектом в FC_Edinet_UpdateBackups_v2.30.27.
   Папка обновления исключается из Git, она не должна загружаться на Vercel.
4. Выполни SQL database/085_admin_editor_role_boundaries.sql в Supabase SQL Editor.
   Проверяй после создания бэкапа. SQL-МИГРАЦИИ: ДА, 085_admin_editor_role_boundaries.sql.
   Эта миграция НУЖНА для ограничения прямых запросов по API.
5. Проверь, что в .env.local задан действующий server-only SUPABASE_SECRET_KEY
   (либо SUPABASE_SERVICE_ROLE_KEY) от ЭТОГО ЖЕ Supabase-проекта.
   Никогда не добавляй ключ с NEXT_PUBLIC_, не отправляй его в чат и GitHub.
6. Открой vercel.com → проект fc-edinet → Settings → Environment Variables →
   SUPABASE_SECRET_KEY → Production. Вставь свой secret API key, сохрани;
   изменения переменных начнут действовать в новом Deployment.
7. Запусти npm run qa:user-roles, затем DEPLOY_FC_EDINET.bat.
   Установщик должен пройти полную проверку TypeScript и next build ДО Git push.
8. После публикации и READY: /api/version должен показать 2.30.27.

ПРАВА
- admin: полный доступ ко всей админке, назначение ролей, системные редакторы.
- editor: новости, медиа, комментарии, игроки, штаб, календарь,
  соревнования, протокол матча, турнирная таблица.
- author: свои новости (существующий авторский сценарий).
- fan: только пользовательский кабинет, без админки.
- На публичном сайте admin/editor видят кнопку-карандаш ТОЛЬКО там,
  где роль допускает редактирование. Клик ведёт непосредственно в
  соответствующую форму с нужным материалом или в список раздела.
- Скрытие ссылки не заменяет проверку прав: серверные layouts/actions и
  SQL restrictive RLS контролируют полномочия.

ТЕСТЫ
1. Под администратором открой /admin/users. Если SUPABASE_SECRET_KEY отсутствует,
   форма создания НЕ показывается, вместо неё инструкция по ключу.
2. Создай тестового editor с временным паролем >=10 символов, проверь логин.
3. Выйди и зайди под editor: только 9 редакторских разделов, системные
   действия, история клуба, статистика сайта, Site Builder недоступны.
4. На /news/<slug> editor видит карандаш и может попасть прямо в редактор новости.
5. На /team/<slug> ведёт к игроку, /matches/<id> — к матчу,
   /media/<slug> — к альбому. /standings — к таблице. На /staff — к штабу.
6. На /club/about, /partners, /academy, / и /statistics карандаш есть только у admin.
7. Автор не может открыть чужую новость напрямую, болельщик не видит карандаш.
8. Из-под editor открой прямую ссылку /admin/users или /admin/site-builder:
   действие должно быть заблокировано сервером, без изменений в базе.
9. НЕ пытайся демотировать последнего администратора в Production; миграция
   содержит защиту от случайного удаления/демоции последнего admin.

- Не выполняй повторно старые SQL-файлы: 078_real_user_monitoring.sql,
  079_multi_competitions.sql, 080_match_schedule_history.sql, 081_cup_results.sql,
  082_cup_bracket.sql, 083_cup_two_leg_ties.sql, 084_fan_notifications.sql.
- Для прежних QA проверок справка: SQL-МИГРАЦИИ: ДА, 084_fan_notifications.sql
  относится только к предыдущему релизу, НЕ выполнять повторно.
- Supabase Security Advisor, PostgreSQL права и Storage policies должны
  быть проверены после применения миграции на отдельном тестовом аккаунте.
- Требуется Node.js 22.x для соответствия package.json, успешный npm build обязателен.
- Git bundle из предыдущей версии содержит КОД, не резервную копию

  Файл с расширением .bundle — проверенный архив предыдущей Git-версии сайта. Он не содержит резервную копию базы Supabase или объектов Storage.
