FC EDINET v2.30.14 FULL — REAL USER PERFORMANCE & ERROR MONITORING
===============================================================
БАЗА: v2.30.13 FULL
SQL-МИГРАЦИИ: ДА — database/078_real_user_monitoring.sql

УСТАНОВКА
1. Сохраните .env.local из предыдущей рабочей версии и резервную копию сайта.
2. В Supabase Dashboard → SQL Editor выполните database/078_real_user_monitoring.sql.
   SQL создаёт только таблицы мониторинга и серверную RPC-функцию; другие разделы не меняет.
3. В Vercel Environment Variables (Production) проверьте наличие секретов:
   SUPABASE_SECRET_KEY (или SUPABASE_SERVICE_ROLE_KEY) и ANALYTICS_IP_SALT.
   НЕ ПРИСЫЛАЙТЕ СЕКРЕТЫ В ЧАТ; НЕ ДОБАВЛЯЙТЕ ИХ В GitHub.
4. Распакуйте этот ZIP в новую папку. Перенесите .env.local в корень.
5. Запустите DEPLOY_FC_EDINET.bat (QA → TypeScript → next build → GitHub push).
   В случае ошибки push НЕ выполняется.
6. Проверьте Vercel Production READY и https://fc-edinet.vercel.app/api/version (2.30.14).
7. Запустите CHECK_PRODUCTION_FC_EDINET.bat для HTTP-проверки.
8. Откройте /admin/diagnostics/performance: переключите 24 часа / 7 дней / 30 дней.
9. Посетите несколько публичных страниц на телефоне и ПК. После первых событий
   отчёт начнёт показывать p75, количество измерений, ошибки и маршруты.

ОГРАНИЧЕНИЯ И ПРИВАТНОСТЬ
- Данные из браузера НЕ содержат IP, cookie, логин, URL-параметры, исходный URL,
  детали ошибок, stack traces, user-agent и идентификаторы посетителя.
- На сервере IP используется ТОЛЬКО для часового HMAC-ограничителя частоты;
  вместо IP временно хранится ротационный хэш. Очищается автоматически.
- Отчёт не включает приватные страницы /admin, /account, /login и /register.
- Система best effort: если Supabase временно недоступен, сайт работает без изменений.
- Ошибки JavaScript показываются счётчиком без подробностей; серверные ошибки
  остаются в системных логах Vercel, которые это обновление не подменяет.
- Показатели не являются лабораторными Lighthouse-результатами.
- Если в отчёте нет данных, это НЕ означает отсутствие ошибок.
- Сбор данных начинается только после установки и публикации; историю задним числом получить нельзя.
- Для полного аудита нужны производственные данные спустя реальные посещения.

Новые SQL-файлы не запускаются установщиком автоматически.
