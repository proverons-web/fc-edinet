FC EDINET v1.5.1
SUPABASE AUTH / RESTORE HARDENING

WHAT WAS HAPPENING

The Supabase project had been paused and was being restored.

During restore:
- Auth could return 502 Bad Gateway
- the browser still had an old Supabase refresh-token cookie
- the old cookie could then produce:
  refresh_token_not_found

v1.5.1 changes the proxy behavior:

1. /api/health bypasses Auth proxy completely.

2. Public users with no Supabase auth cookie do NOT trigger an Auth request
   on every page.

3. Temporary Auth upstream failures (including 502) are caught in proxy.ts
   and do not break public pages.

4. A stale Supabase auth cookie returning status 400 /
   refresh_token_not_found is automatically expired.

NO DATABASE SQL IS REQUIRED.

USE

1. Copy .env.local from v1.5 into v1.5.1
2. npm install
3. npm run build
4. npm run dev

If the browser still shows an old session once:
- open localhost:3000 in a private/incognito window, OR
- clear site data/cookies for localhost:3000

HYDRATION WARNING

Attributes such as:
  data-bybit-channel-name
  data-bybit-is-default-wallet

are injected by a Bybit browser extension before React hydration.
They are not generated by FC Edinet code.
Disable the extension for localhost if you want the warning to disappear.
