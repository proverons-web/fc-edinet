FC EDINEȚ v2.29.14 — UI CONSISTENCY & CSS CLEANUP

ОСНОВА: полная версия v2.29.13. Дизайн и поведение сайта намеренно не менялись.

ИЗМЕНЕНИЯ
1. Удалены 215 ранних CSS-деклараций, которые полностью совпадали с более поздними по селектору, условию @media, свойству, значению и !important.
2. Количество !important снижено с 4238 до 4080. Новый лимит закреплён в qa/css-baseline.json.
3. Добавлена проверка визуальной идентичности: 5 контрольных экранов x 4 размера (320, 390, 768, 1280 px); старые и новые стили сравниваются в одном Chrome/Edge.
4. Исправлены устаревшие проверки, привязанные к фиксированному номеру версии: теперь qa:live и qa:public-integrity используют package.json.
5. Новая проверка включена в qa:all, deploy:check и GitHub Actions.
6. Миграции Supabase не требуются.

УСТАНОВКА
1. Распаковать fc-edinet-v2.29.14 рядом с предыдущими версиями в E:\Projects\FC Edinet\.
2. Сохранить предыдущую папку с рабочим .env.local. Новый архив не содержит секретов.
3. Запустить DEPLOY_FC_EDINET.bat.
4. Дождаться завершения всех восьми шагов: проверка кода, production build, GitHub и Vercel.
5. После публикации проверить https://fc-edinet.vercel.app/api/version — версия должна быть 2.29.14.
6. Выполнить npm run qa:live в новой папке, затем визуально проверить страницы на ПК и телефоне.

ЛОКАЛЬНЫЕ ПРОВЕРКИ
npm run qa:site
npm run qa:css
npm run qa:ui
npm run qa:responsive
npm run qa:all
npm run build

ВАЖНО
- npm run qa:ui сравнивает синтетические HTML-макеты, а не закрытые страницы реального сайта.
- qa:ui:baseline использовать ТОЛЬКО для утверждённого изменения внешнего вида; обновление эталона без проверки скриншотов скрывает регрессии.
- В проекте остаётся значительный исторический CSS-долг: 4080 !important. Не удаляйте другие правила без визуальной регрессии.
- В репозиторий запрещено включать .env.local и другие локальные секреты.
