FC EDINEȚ v2.8.1 — USER MANAGEMENT + ADMIN POLISH / PHASE 16

Changes:
- administrators can create users directly from /admin/users
- new account form supports email, display name, temporary password and role
- existing role model is preserved: fan / author / editor / admin
- when SUPABASE_SECRET_KEY is configured, new users are created confirmed and ready to sign in
- without the secret key, a safe isolated signup fallback is used; email confirmation may be required
- administrators can change roles of existing users using the protected admin_set_user_role RPC
- user block/unblock controls are available when SUPABASE_SECRET_KEY is configured
- current administrator cannot demote or block their own account from this page
- server-only Supabase secret is never exposed to browser code
- redesigned user-management page matches the v2.8 admin shell and is responsive
- deploy check reports whether full user-management mode is configured

Recommended Vercel configuration:
1. Supabase Dashboard -> Project Settings / API -> Secret key (or legacy service_role key).
2. Vercel -> Project -> Settings -> Environment Variables.
3. Add SUPABASE_SECRET_KEY (server-only; NEVER prefix it with NEXT_PUBLIC_).
4. Redeploy.

No SQL migration required. Existing database/015_admin_users.sql remains the role-management layer.

Deployment:
1. Copy the working .env.local from the previous version.
2. Optionally add SUPABASE_SECRET_KEY to .env.local for full local user-management features.
3. Run DEPLOY_FC_EDINET.bat.
4. Verify /api/version -> 2.8.1.
5. Open /admin/users and create a test account.

Additional Admin UX fix:
- Site Builder editor iframe now opens admin editors in embedded mode
- duplicated inner Admin sidebar/topbar is removed from the editor pane
- public Header/Footer are also suppressed inside embedded admin editors
- the "На весь экран" editor link still opens the normal full admin page
